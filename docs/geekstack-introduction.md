# 极客栈 GeekStack

> **代码江湖的落脚点** —— 为开发者而生的技术社区平台
> 项目分享 × 技术专栏 × 开发者论坛，一个入口，三重归属

---

## 一、极客栈是什么

**极客栈（GeekStack）** 是一个面向开发者的垂直技术社区平台，围绕开发者最真实的三类需求构建：

- **晒出作品** —— 项目分享广场：展示你的项目，挂接 GitHub / Gitee 仓库，一键导入、Star 同步、标签归档
- **沉淀知识** —— 技术文章：Markdown 长文写作，代码高亮渲染，分类归档，搜索直达
- **找到同好** —— 开发者论坛：分类讨论、两级回帖、点赞互动、热帖榜单、站内通知

从发布第一行代码，到被更多人看见、讨论、点赞——**整个旅程在一个社区里闭环**。

---

## 二、产品特性

### 🏮 项目分享 · 让作品被看见

- **一键导入仓库**：绑定 GitHub / Gitee 账号，公开仓库自动同步，从"我有项目"到"项目已发布"只需一次点击
- **标签体系**：技术栈标签 + 全站标签云，热度排序，让同类项目互相找到
- **浏览与点赞**：原子计数、热度加权排序，好项目不会被时间线埋没
- **可见性控制**：草稿、下架随时切换，作者视角完整保留

### 📖 技术文章 · 让经验被沉淀

- **Markdown 长文写作**：专业编辑器，实时渲染，代码高亮
- **分类归档**：Java、AI、问答、资源分享等频道，各归其位
- **全文搜索**：跨帖子、跨项目的关键字检索， denied 内容永不出现
- **个人主页**：每个开发者一个聚合页——文章、项目、仓库、动态一屏呈现

### 💬 开发者论坛 · 让交流有回响

- **两级回帖**：直接回复 + 楼中楼，讨论结构清晰
- **站内通知**：被回复、被点赞实时触达，顶栏红点直达
- **热帖榜单**：回复 × 3 + 浏览 + 点赞 × 2 的加权算法，24 小时热榜实时更新
- **关注机制**（规划中）：关注感兴趣的开发者，信息流按人订阅

## 三、技术架构

### 架构原则：模块化单体，为演化而设计

不做微服务幻觉，也不做大泥球——**按业务域分包的单体架构，包结构即未来的服务边界**：

```
com.community
├── user      # 用户与认证（JWT + OAuth2）
├── share     # 项目分享
├── forum     # 技术论坛
├── like      # 点赞收藏
├── notify    # 站内通知（事件驱动）
├── hot       # 热榜计算（Redis ZSet）
├── search    # 搜索与标签发现
├── oauth     # 第三方仓库同步（AES-GCM 加密）
├── event     # 事件总线（跨模块通信唯一通道）
└── common    # 统一响应、异常、加密、工具
```

**模块间只经 Service 接口与事件总线通信，禁止跨模块触碰数据层**——这条纪律由架构守护测试与七轮人工评审共同执行。

### 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Java 17 · Spring Boot 3.3 · Spring Security 6 · MyBatis-Plus |
| 前端 | Vue 3.4 · TypeScript 5 · Vite 5 · Naive UI（深度定制主题） |
| 数据 | MySQL 8.0（Flyway 版本化迁移） · Redis 7（热榜 ZSet + 缓存） |
| 认证 | JWT 双令牌 · GitHub / Gitee OAuth2 · **Token AES-GCM 加密落库** |
| 部署 | Docker Compose（Nginx + 应用 + MySQL + Redis）· GitHub Actions CI |

## 四、工程质量：用数字说话

我们不宣称"高质量"——我们**度量**它。

| 维度 | 数据 |
|------|------|
| 自动化测试 | **99 个**集成/单元测试，CI 全绿合入 |
| 评审轮次 | **7 轮**里程碑评审 + 每任务实测复核（评审人不采信自测汇报，全部独立复跑） |
| 安全基线 | 零明文凭据入库 · OAuth Token 加密存储 · XSS 渲染白名单唯一出口 · SQL 全参数化 |
| 无障碍 | WCAG AA 对比度全站达标（脚本化验证）· 键盘可达 · 焦点环 · 尊重 `prefers-reduced-motion` |
| 性能 | 核心接口 P95 < 30ms · 慢 SQL（>200ms）零记录 · 首页聚合 60s 缓存 |
| 灾备 | 每日自动备份 + 异地容灾 + **恢复演练两次实测通过** |
| 交付纪律 | 每次合入附 CI 证据 · 新参数必带正/反/越权三路测试 · flaky 测试零容忍 |

**一个例子**：我们的热榜排序接口在 24 小时窗口内按 `回复×3 + 浏览 + 点赞×2` 加权计算——排序公式、稳定序保证、Redis 降级路径，各自有独立测试覆盖；Redis 宕机时自动降级数据库排序，**用户无感**。

## 五、设计系统：夜栈灯码

极客栈的视觉语言有名字、有哲学：**「夜栈灯码」**——深夜客栈的墨蓝底色，一盏琥珀灯笼照亮该照亮的地方。

- **唯一强调色纪律**：琥珀色只出现在品牌、点睛词、主按钮、交互反馈四处——"照亮该照亮的地方，不刷满整间屋子"
- **OKLCH 色彩空间 + 两层 Token 架构**：primitive 固定，semantic 随主题切换，日/夜双主题一套语义
- **编辑部式排版**：信息流是排版驱动的列表行，不是卡片堆叠；专业字体组合（Space Grotesk × 霞鹜/苹方）
- **完整状态设计**：骨架屏、引导空态、可诊断错误态、统一焦点环——四种状态一个不少
- **去 AI 味自查**：8 项"AI 生成审美指纹"逐条修正，只留下人的设计判断

## 七、极客栈的边界（我们暂不做什么）

- **不做管理后台幻觉**：内容审核队列与 RBAC 架构插槽已预留，用户规模到了即插即用
- **不做微服务幻想**：日活万级以内，单体 + 事件总线就是最优解；边界已按服务拆分标准划定
- **不做算法投喂**：时间线按时间与热度排序，把选择权还给开发者
