# T-DESIGN-1 · 设计现状与差距评估

> 交付人：UI 设计师 ｜ 日期：2026-09-08 ｜ 性质：纯评估，未改动任何代码
> 范围：`frontend/src/theme/tokens.ts`、`tokens.css`、`App.vue`、`MainLayout.vue` 及核心页面（登录 / 项目广场 / 帖子详情 / 个人主页 / 发布页 / 论坛列表 / 全局 404）

---

## 一、总体结论（先说重要的）

1. **现状是浅色主题，不是交底时说的"深色主题"。** `App.vue` 只挂了 `naiveThemeOverrides`，未引入 naive-ui 的 `darkTheme`；`tokens.css` 的底色是 `#f1f3f5` 灰底 + 白色卡片 + 深色文字 `#182431`。**需要 PM 裁决**：是交底口径有误，还是"深色主题"是未实现的需求？这直接影响后续"增强"还是"重构"的决策。
2. **Token 体系地基是好的，但覆盖极薄。** 现有 13 个 Token（色彩 9 + 圆角 2 + 字号 1 + 字体 1），双文件同源（ts 供 naive-ui，css 供组件样式），换肤架构成立。但间距、字号阶梯、阴影、边框色、禁用态、暗色对等维度完全缺失。
3. **组件层 Token 纪律整体良好，存在少量越界。** 全站扫描到 4 处硬编码 `color: #fff`（均为品牌蓝底上的前景白字，视觉上可接受，但属于 Token 体系外的"游离值"），以及 1 类语义误用（用 `--color-bg-layout` 当分隔线/边框色）。
4. **WCAG AA 预检：核心文字全部达标，3 类色彩组合不达标**（详见第三节）。
5. **零响应式。** 项目广场卡片网格固定 `repeat(3, 1fr)`，无任何媒体查询，移动端/窄窗口会直接挤压变形。

## 二、现有 Token 覆盖盘点

### 2.1 已覆盖（值得肯定）

| 维度 | 内容 | 评价 |
|---|---|---|
| 品牌色 | `#0a59f7`（华为蓝）+ hover `#3178ff` + pressed `#0540b4` | 三态完整，符合鸿蒙规范 |
| 语义色 | success `#34c724` / warning `#ff9500` / error `#fa383e` | 有，但仅作背景/图标用（见 3.2 问题） |
| 底色 | layout `#f1f3f5` + container `#ffffff` | 两级够用 |
| 文字 | primary `#182431` + secondary `#5e6772` | 两级，够用但偏少 |
| 圆角 | 12px / 8px | 鸿蒙标志性大圆角，方向正确 |
| 双通道架构 | ts → naive-ui common 覆盖；css → `:root` 变量 | 同源换肤，架构正确 |

### 2.2 缺失清单（对照鸿蒙设计规范）

| 缺失维度 | 现状 | 影响 |
|---|---|---|
| **字号阶梯** | 仅 `fontSize: 14px` 一个值；页面里 12/13/15/16/18/20px 全是散落的硬编码 | 层级靠手感，无规范可依 |
| **间距系统** | 无 Token；页面用 4/6/8/10/12/16/20/24/28/64px 十余种散值 | 尚未失控（多数落在 8 的倍数附近），但扩展必乱 |
| **阴影/海拔** | 无；卡片无边框阴影，仅 naive-ui 默认 | 缺乏层级感，鸿蒙规范要求明确的海拔体系 |
| **边框/分隔线色** | 无；用 `--color-bg-layout` 兼职当边框色（`PostDetailView`、`ProfileView` 的 `border-bottom`、`border-left`） | 语义误用：换肤时"背景灰"和"分隔线灰"会被一起改，埋雷 |
| **品牌底上的前景色** | 无（4 处硬编码 `#fff`） | 换浅色品牌时白字不可读 |
| **暗色主题** | 完全没有 | 若深色是需求则为最大缺口 |
| **焦点/键盘态** | 无自定义 focus-visible；论坛分类 chip、发帖分类按钮是原生 button 但无 hover/focus 样式 | 键盘可达性 + 视觉反馈缺口 |
| **字体资产** | 声明了 `HarmonyOS Sans SC` 但无任何 @font-face / 字体包引入 | 实际渲染回落到 PingFang/雅黑，"鸿蒙风"字体是空的 |
| **动效** | 无 Token；仅 naive-ui 内置过渡 | 鸿蒙规范有明确动效曲线体系（弹性/标准），暂未建立 |
| **断点** | 无 | 响应式为零的直接原因 |

## 三、WCAG AA 预检结果（暗色主题下的检查说明）

预检基于当前实际生效的浅色 Token 计算（WCAG 对比度与主题明暗无关，公式通用）。**若后续切暗色主题，需用同样的矩阵重算一遍**——暗色下风险最大的正是品牌蓝 `#0a59f7` 作正文色（暗底蓝字通常不达标）。

### 3.1 达标项 ✅

| 前景/背景 | 对比度 | 场景 |
|---|---|---|
| `#182431` / `#ffffff` | **15.72:1** | 正文 / 卡片 |
| `#182431` / `#f1f3f5` | **14.14:1** | 正文 / 页面灰底 |
| `#5e6772` / `#ffffff` | **5.74:1** | 次要文字 12-13px / 卡片 |
| `#5e6772` / `#f1f3f5` | **5.16:1** | 次要文字 / 页面灰底 |
| `#0a59f7` / `#ffffff` | **5.55:1** | 品牌色链接、repo 名、nav 激活态 |
| `#0a59f7` / `#f1f3f5` | **4.99:1** | 品牌色文字 / 灰底 |
| `#ffffff` / `#0a59f7` | **5.55:1** | 主按钮、激活 chip、头像白字 |

### 3.2 不达标项 ❌（按严重度排序）

| # | 前景/背景 | 对比度 | 场景 | 说明 |
|---|---|---|---|---|
| F1 | `#34c724`（success）/ `#ffffff` | **2.25:1** | naive-ui success 标签/徽标中的彩色文字 | 全场景不达标（连大字 3.0 都不够） |
| F2 | `#ff9500`（warning）/ `#ffffff` | **2.20:1** | "置顶""已下架"等 warning 标签文字 | 同上；且这两个标签信息承载真实语义 |
| F3 | `#fa383e`（error）/ `#ffffff` | **3.68:1** | error 标签文字、"管理员"标签、删除按钮文字 | 小字号（12-14px 常规）下不达标 |
| F4 | `#ffffff` / `#3178ff` | **3.99:1** | 主按钮 hover 态白字 | 悬停瞬间掉到 4.5 以下，13-14px 不属"大字"豁免 |

> 修复方向（仅建议，待批准）：标签场景改用 naive-ui 的着色底模式（tinted bg）让彩色文字变深色变体，或直接调深语义色文字变体；hover 态可通过保留深蓝底或降低白字透明度补偿。均属 Token 层增强，可纯样式解决。
