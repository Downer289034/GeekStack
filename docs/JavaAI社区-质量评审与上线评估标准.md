# Java & AI 交流社区 — 项目质量评审与上线评估标准

> 用途：项目开发完成后，由高级项目经理按此标准执行质量评审与上线评估（Go / No-Go 决策）。
> 使用方式：开发完成任意里程碑后通知 PM，PM 按对应章节逐项评审并出具报告。

---

## 一、评审触发时机

| 时机 | 评审范围 | 产出 |
|------|---------|------|
| M1 MVP 开发完成 | 代码质量 + MVP 功能验收 + 上线评估 | 《MVP 评审报告》+ 上线 Go / No-Go 结论 |
| M2 / M3 迭代完成 | 增量功能 + 架构一致性抽查 | 《迭代评审报告》 |
| 上线后 30 天 | 生产运行复盘（故障、慢 SQL、用户反馈） | 《运行复盘》 |

---

## 二、代码质量评审清单

### 2.1 架构一致性（对应规划文档第二节）
- [ ] 包结构按业务域划分（user/oauth/share/forum/notify），无跨模块直访 Mapper
- [ ] Controller 无业务逻辑；统一响应体 `Result<T>`、全局异常处理全覆盖
- [ ] 跨模块副作用走 `ApplicationEvent`，无模块间硬编码调用
- [ ] 所有接口挂 `/api/v1`，无版本遗漏

### 2.2 代码规范
- [ ] Checkstyle / ESLint 全绿，CI 拦截生效
- [ ] 无魔法值、无复制粘贴超过 3 处的重复代码块
- [ ] 关键路径（登录、OAuth 回调、发布流程）有注释与日志

### 2.3 安全（一票否决项）
- [ ] 无明文密码 / Token / 密钥入库或进代码库（抽查 git 历史）
- [ ] OAuth Token AES-GCM 加密，密钥来自环境变量
- [ ] Markdown 渲染经 DOMPurify 消毒；接口参数校验完整（防注入、越权：抽查"改他人资源"用例）
- [ ] JWT 过期与刷新逻辑正确，登出后凭据失效

### 2.4 数据与性能
- [ ] 所有删除为逻辑删除；列表接口全部分页
- [ ] 关键索引齐全；无 >200ms 慢 SQL
- [ ] 全部表字段与迁移脚本（Flyway）一致，无手工改库

## 三、功能验收清单（对照任务清单逐条打勾）

- [ ] Task 1–18 全部验收标准满足（以任务清单文档为准，逐条核对）
- [ ] 核心用户旅程实测走通：注册 → 绑定仓库 → 分享项目 → 论坛发帖回帖 → 他人可见
- [ ] 异常路径实测：未登录访问受限页、仓库 API 限流降级、编辑器提交空内容

## 四、上线评估（Go / No-Go）

### 4.1 必须全部满足（任何一项不满足即 No-Go）

| # | 项目 | 标准 |
|---|------|------|
| 1 | 部署 | 公网 HTTPS 可访问，Docker Compose 一键拉起，无手工配置步骤遗漏 |
| 2 | 备份 | MySQL 每日自动备份到独立存储，且**做过一次恢复演练** |
| 3 | 安全 | 2.3 节一票否决项全部通过 |
| 4 | 日志与监控 | 错误日志落盘可查；进程退出自动重启（restart 策略）；磁盘/内存告警可用 |
| 5 | 合规 | ICP 备案完成；页脚有备案号；无违法内容风险 |

### 4.2 建议满足（不影响 Go，但需记录为上线后任务）
- [ ] 简易内容应急处理脚本（无管理端期间的删帖/封禁手段）
- [ ] 压测报告：核心接口在预期并发下可用
- [ ] 回滚方案：上一版本镜像可 10 分钟内回滚

### 4.3 结论格式
```
评审结论：GO / NO-GO / 有条件 GO（列出条件与期限）
风险清单：按 高/中/低 列出，注明责任方与解决期限
```

---

## 五、PM 评审工作方式（约定）

1. 开发完成后，你在会话里说"开始评审 + 里程碑"，并告知代码位置（仓库或本地路径）。
2. PM 做静态评审（读代码、查配置）+ 可运行验证（按验收标准实测），必要时用浏览器实测页面。
3. 评审报告写入 `docs/`，问题按 **P0 阻断上线 / P1 上线后一周内修 / P2 记入扩展池** 分级。
4. 评审只对标准不对人——目的是把关质量，不是挑刺。
