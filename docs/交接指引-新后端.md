## 三、已知坑位清单（前人踩过的，别再踩）

### 环境
- **双栈拓扑（新后端第一坑）**：生产栈 `/opt/community`（geekstack-*，**3306/6379 故意不对外暴露**）+ 开发栈 `/opt/community-dev`（community-*，**3306/6379 供本地开发连接**）。本地启动应用连的是 **dev 栈**——服务器重启后 prod 会自动拉起但 dev 可能没起，症状是 `Communications link failure / Connection refused` 而"运维检查一切正常"（他看的是 prod）。修复：`cd /opt/community-dev && docker compose up -d`，本机 `bash -c "echo > /dev/tcp/172.25.41.137/3306"` 验证可达后再启动
- **Git Bash 下 `mvn` 会报 Launcher 错**——用全路径 `"D:/Maven/apache-maven-3.9.2/bin/mvn.cmd"` 或 PowerShell 的 `mvn.cmd`
- **本机 Windows 原生 MySQL 占用 3306**——`127.0.0.1` 连的是它不是 WSL 容器；开发库必须走 `172.25.41.137`
- **WSL2 空闲自动关机**——服务器失联先怀疑这个，重启即恢复，容器自动拉起
- **Windows Defender 会锁新构建的 jar**——`repackage` 报 `Unable to rename` 是文件锁不是代码问题，重跑或稍等
- PM 沙箱内前端 build 需 `--emptyOutDir false`（删除保护）

### MyBatis-Plus 3.5.12 断代变更（重要）
- `FieldStrategy.IGNORED` **已删除**→ 用 `ALWAYS`（否则全项目 Lombok 级联编译错）
- `PaginationInnerInterceptor` 拆到独立构件 `mybatis-plus-jsqlparser`，需单独引依赖
- `selectPage` + `wrapper.last("LIMIT n")` 会**双重拼 LIMIT** 报 SQL 错——二选一
- 实体主键用 `IdType.AUTO`（数据库自增）——**别改回 ASSIGN_ID**，雪花 ID 19 位超出 JS 安全整数，前端 JSON 解析丢精度
- `@Transactional` 标在**同类内部调用**的方法上是死注解（绕过 Spring 代理）——跨方法事务用 `TransactionTemplate`

### 业务口径（改错会出线上问题）
- 计数（view/reply/like）一律 `setSql` 原子更新 + `GREATEST` 兜底 0；回帖计数唯一写入点在 `PostMutationSupport`，**别在别处写计数**
- 隐藏内容两套口径：share 的 HIDDEN = "作者视角可见"，repo 的 hidden = "对所有人隐藏"——别混
- 删除一律逻辑删除；编辑/下架等归属操作走 `requireOwned` 模式（404 先于 403）
- **Flyway 已执行文件禁止回改**（checksum 灾难），只允许 V4/V5 增量
- **`package-info.java` 不是空文件**——是包级架构文档，必读、必留、新模块要写

## 四、红线（违反 = 评审退回）

1. 密钥/凭据不进 git、不进聊天、不进日志（`.env` 已隔离，保持）
2. 模块间只走 Service 接口 + 事件总线，**禁止 import 别的模块的 Mapper**
3. Controller 不写业务；Markdown 渲染全站唯一出口（前端 `markdown.ts`）
4. 新增请求参数必须带正/反/越权三条测试路径
5. 回报必须附 `mvn verify` 输出末行或 CI run 链接（`mvn.cmd -B verify`）
6. 异步断言用轮询等待（参考 `NotifyIntegrationTest.waitForNotification`）——flaky 测试 = 退回
7. 降级/异常路径必须有测试钉死（参考 `HotPostServiceTest` 的 @TestConfiguration 模式）
